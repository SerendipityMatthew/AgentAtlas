# Agent Atlas · 产品与 UI/UX 改进方案

> 2026-11-18 · 保持当前编辑体感 + 补齐信息架构 / 阅读 / 交互 / 响应式

## 定位再确认

Agent Atlas 是**一本可阅读、可查、可实验的交互式技术书**。
- **不是** AI 工具导航站 / SaaS Dashboard / 新闻站 / 博客
- **是** 读者可以从头翻到尾(深入课), 可以按词查(术语库), 以后可以动手玩(实验)的"小书"

视觉与交互的所有决策回到这条上。

---

## 现状强项(保)

| 项 | 现状 |
|---|---|
| 色系 | 暖米底 + 深绿强调 + 7 组 pastel, 整体安静、不刺眼 |
| 字体 | Noto Serif SC + Fraunces + JetBrains Mono 的中英混排, 像书不像后台 |
| 节奏 | 4 步课堂结构稳定, 用户学会一节=学会所有节 |
| 术语库 | 7 组地图 + 分组词条是现成的"全局视图", 在同类产品里少见 |
| 键盘 | ← / → / Space / R 很顺手 |

**这些不改。**

## 现状短板(改)

### 1. 信息架构
- 首页没有"你现在在整本书哪一章"的指示
- 术语库首页进去直接是地图, 看不到"词和词之间依赖关系"(地图只按组分)
- 深入课之间没显示先后顺序 / 建议阅读顺序

**改法**:
- 全站左侧加一个可折叠的全书目录(desktop), 当前位置高亮
- 术语库在分组下加"入门 vs 进阶"标签(词卡数据加 `level` 字段)
- 每节开头加 "读完这节你会..." 与 "前置: 建议先读 X"

### 2. 阅读体验
- 术语在课程文案里是纯文字(没链接)
- 代码块不能复制
- 术语卡的 4 块布局好, 但没有"看错不该看"提示(简报要求的区分)

**改法**:
- 课程文案里的术语自动匹配并包 `<a data-term>` + hover 显示一句话 + 点击跳
- 每个 `<pre>` 右上角加一个 copy 按钮
- 术语卡加第 5 块(可选): "别和 X 混 —— 它的区别是..."

### 3. 交互深度(最关键)
当前**没有实验**。简报要求的 5 个 Simulator 是这一轮最重要的升级。

详细设计见下方 "实验组件" 节。

### 4. 响应式
现状只有一条 `@media (max-width: 920px)` 兜底, 做法是把网格压成单列。问题:
- 术语库地图 SVG 在 375px 上文字太小
- 深入课的 `.canvas` 保持 4:3, 在手机竖屏里被压很扁
- 顶部 tab + logo + lesson-nav 三段式, 在窄屏会溢出

**改法**:
- 两档断点: 小于 640 (手机) / 小于 1024 (平板)
- 手机上:
  - 顶部: logo + 汉堡菜单(里面装 tabs + lesson-nav)
  - 术语库地图: 换成一张"组名列表 + 微型地图缩略图"
  - 深入课 canvas: 保持 1:1 或自适应, 不强制 4:3
  - 右侧 panel 变成下方 sheet (类似 mobile reader 的"工具抽屉")
- 平板上基本沿用 desktop 布局, 收紧外边距

### 5. 编辑体细节(简报点名)
- 避免: 过度渐变 / 玻璃拟态 / 过多卡片 / 过多 emoji / 装饰性动画
- 现状问题:
  - 首页 glossary-CTA 用了淡粉渐变 → 保留(低饱和没问题)
  - callout 里用了 💡 🔑 ⚙ 📐 🔀 等 emoji → 减到最小(保留 💡 做"核心一句话", 其他换纯 label)
  - "本节完成 ✓" 的勾用 ✓ 字符, OK
  - 时间线圆点 + 连线 → 继续用
  - 过渡动画: 现有 fade+translateY 0.45s / arrow draw 0.9s, 节奏合适, 不改

## 实验组件(新增, 简报 Phase 3)

每个实验: v1 用**纯 mock 数据**, 清晰的教学目标, 别过度花哨。

### E1 · Prompt Playground
**教学目标**: 直观看到 "换 system prompt, 行为完全变" (呼应 Lesson 2 Step 3)

**界面**:
```
┌─ system prompt ─────────┐ ┌─ 风格预设 ────────────┐
│ textarea (可编辑)       │ │ ○ Python 专家 (默认)   │
│                          │ │ ○ 幼儿园老师          │
│                          │ │ ○ 客服, 礼貌正式      │
└─────────────────────────┘ │ ○ (自定义)             │
                             └──────────────────────┘
┌─ user prompt ──────────┐
│ "怎么读 JSON 文件?"     │
└────────────────────────┘
      ↓ [ 运行 ]
┌─ 模型回应 (模拟) ─────────────────────────────┐
│  with open("f.json") as f:                      │
│      data = json.load(f)                        │
│  // (匹配当前 system 的 预设输出)              │
└─────────────────────────────────────────────────┘
```

**实现**: 字典 `{(system_hash, user_hash) → canned_response}`, 匹配不到就展示 "没有预设, 请选预设 prompt"

### E2 · Agent Workflow Simulator
**教学目标**: 直观看完一次 Agent 的 ReAct 循环(呼应 Lesson 5)

**界面**: 时间线 + 可逐步展开 / 可播放

```
   t=0  user: "订周五去北京的机票"
        ├─ ▶ (点一下展开)
   t=1  LLM: "需要先查航班" → tool_call(search_flights)
   t=2  tool: [{price: 1200, time: "09:00"}, ...]
   t=3  LLM: "选最便宜" → tool_call(book_flight, flight_id)
   t=4  tool: {ok: true, order_id: ABC123}
   t=5  LLM: "订好了, 发邮件" → tool_call(send_email)
   t=6  tool: {sent: true}
   t=7  LLM: "已订 ... 确认邮件已发"
```

**控制**: ▶/⏸ / ⏮/⏭ / 可点任一条展开"原始 messages"

**变体**: 加一个 "翻车模式": 重跑一遍但 tool_call 返回 500, 展示 retry/fallback

### E3 · MCP Simulator
**教学目标**: 讲清 Host / Client / Server / Tools 四者

**界面**: 一张大的交互 SVG, 四个区域:
```
┌─────────────┐       ┌─────────────┐
│   MCP Host  │ ←───→ │  MCP Client │
│ (Claude、   │       │  (宿主里的   │
│  Cursor)    │       │   连接层)    │
└─────────────┘       └──────┬──────┘
                              │ stdio / SSE
                              ↓
                      ┌──────────────┐
                      │  MCP Server  │
                      │  (Slack/DB/  │
                      │   file...)   │
                      └──────┬───────┘
                             │
                 ┌───────────┼───────────┐
                 ↓           ↓           ↓
              tools    resources     prompts
```

每个区域点一下 → 右侧 panel 显示它的职责 + 一段代码 + 常见误区。

### E4 · RAG Simulator
**教学目标**: Chunk size 和 Top-K 怎么影响检索质量

**界面**:
```
预置语料: 10 段公司员工手册

┌─ 控制 ─────────────────┐
│ Chunk size: [500] ----  │
│ Top K:      [3] ----    │
│ Query: "退款多少天内?"  │  [ 检索 ]
└────────────────────────┘

┌─ 检索到的块 ─────────────┐
│ 1. (chunk_id=4) "...30 天...退款..." 相似度 0.87 │
│ 2. (chunk_id=1) "...公司简介..."          0.62 │
│ 3. (chunk_id=7) "...退换货..."             0.59 │
└──────────────────────────┘

┌─ 送进 LLM 的 prompt ────┐
│ "基于以下: [块1] [块2] [块3]"              │
└──────────────────────────┘

┌─ 模拟回答 ───────────────┐
│ "30 天内可以申请退款..."                      │
└──────────────────────────┘
```

**实现**: 预先把 10 段 corpus 的 embedding 算好存 JSON, 浏览器里 cosine similarity 排序

### E5 · Memory Simulator
**教学目标**: 短期上下文 / 持久化 / 检索式记忆的区别

**界面**: 三栏对照
```
          │ 无记忆         │ 短期上下文    │ 长期(RAG式)   │
──────────┼──────────────┼──────────────┼──────────────┤
第 1 轮:  │ "我叫张三"    │ ...相同      │ ...相同       │
第 2 轮:  │ "我叫啥?"      │              │              │
         │ → "你没告诉我" │ → "张三"     │ → "张三"      │
一周后:   │              │              │              │
         │ → "你没告诉我" │ → "你没告诉我" │ → "张三"    │
                                        (查上周存的 note)
```

## 案例库(简报 Phase 4)

6 个循序渐进的案例, 每个独立一页, 不混进课程体系:
1. 邮件助手(最简, 只用 LLM)
2. PDF 分析(加 chunking/embedding)
3. 浏览器自动化(加 tool)
4. MCP 天气查询(加 MCP)
5. 代码审查(加结构化输出)
6. 多 Agent 协作(加 orchestration)

每案例固定模板: 需求 / 架构图 / 工作流 / 核心概念链接到课程 / 代码 / 常见错误 / 安全注意 / 延伸。

可选 Python + TypeScript, 用 tab 切换。

## 视觉变化总结

| 类别 | 变化 |
|---|---|
| 色 / 字 | 不变 |
| 配色重心 | 保持 7 组色; 实验组件用更饱和的变体以区分"读 / 玩" |
| emoji | 减到最小(保留 💡 做"核心一句话" callout, 其他换 label) |
| 卡片 | 保留; 不增加新卡片变体 |
| 动画 | 保留现有; 实验组件的动画要为"展示机制"服务, 不花哨 |
| 深色模式 | 新增(简报没强制, 但是编辑体产品常规) |
